# مختبر توافق محلي لمطعمين وهميين

هذه حزمة تجربة للخطوة BUILD-01 من المواصفة، وليست نشر إنتاج أو تنفيذ Menyona Core. يشترط تشغيلها موافقة المراجع الأمني على النسخة المحددة وفق AGENTS.md. لا تعني الفحوص المحدودة اجتياز AC-03 أو AC-19 أو AC-20 كاملة.

صورة Caddy مشتقة من بصمته المثبتة بإزالة file capability الخاصة بربط المنافذ المنخفضة أثناء البناء؛ يستعمل المختبر المنفذ 8080 ولا يحتاجها. يبقى التشغيل nonroot وcap_drop ALL وno-new-privileges.

يستخدم المختبر صور WordPress وMariaDB المثبتة بالبصمة في components.lock.json، وWooCommerce وStorefront وترجمة عربية من مصدر WordPress الرسمي مع SHA-256 وحجم لكل أرشيف. البصمة تثبت ثبات التنزيل المقبول ولا تمثل توقيع ناشر مستقلًا. تبقى تراخيص المكونات الأصلية داخلها؛ لا يعاد نشر ملفاتها أو إسناد ترخيص جديد للمشروع.

لكل مطعم شبكة Docker داخلية وقاعدة ومستخدم وأسرار ووسائط ووحدة شيفرة منفصلة. الويب يعمل بحساب www-data، والقاعدة بحساب mysql، مع إسقاط القدرات وملفات نظام للقراءة وحدود ذاكرة وCPU وPIDs وسجلات. المنفذان 18981 و18982 مقيدان بـ127.0.0.1؛ لا يُنشر منفذ قاعدة البيانات. يمر وصول المضيف المحلي عبر وكيل Caddy HTTP لكل مطعم، مفصول عن شبكة القاعدة مع upstream ثابت وإدارة معطلة؛ لا يمثل هذا قبول HTTPS للإنتاج. يمنع خروج HTTP من WordPress والبريد، وتُعطل WP-Cron والتحديثات في هذا المختبر. لا يمثل ذلك تصميم عامل الإنتاج الذي ما زال يحتاج التنفيذ.

يمكن تعيين LAB_STATE_PARENT لمجلد خاص آخر وLAB_CHROMIUM_EXECUTABLE لمسار متصفح موثوق؛ تسجل بصمة المتصفح وتتحقق قبل التشغيل. يكرر workflow المخصص التجربة على عامل GitHub مؤقت دون مفاتيح مزود أو بيانات حقيقية.

الأسرار اصطناعية فريدة محفوظة خارج المستودع في مجلد خاص صلاحياته 0700، ولا تدخل صورة Docker أو مخرجات عامة. حساب التهيئة الإداري محجوب من تسجيل دخول الويب. ملفات مساعدة CLI خارج جذر الويب، ولا توجد أداة دفع تجريبية عامة. الانتقال إلى paid يستدعي payment_complete محليًا فقط؛ لا اتصال ببوابة ولا دليل قبول تحصيل أو استرداد.

## التحضير والتشغيل

يتطلب التشغيل Docker وCompose وPython 3 وNode/npm، وChromium المحلي عند المسار الذي يتحقق منه البرنامج. يتطلب 5 GiB فراغًا عند التحضير و4 GiB قبل التشغيل. تستعمل الموارد المتاحة دون حذف صور أو بيانات أي مشروع آخر. تستهدف حدود المختبر ست حاويات بحد ذاكرة إجمالي يقارب 1.8 GiB، إضافة إلى المتصفح ومرحلة البناء؛ هذا ليس قياس سعة إنتاج.

أولًا جهز السياق الخاص والتبعيات دون تشغيل المتاجر:

```bash
python3 scripts/run_compatibility_lab.py prepare
```

يطبع الأمر مسار حالة خاصًا. ينزل التبعيات المثبتة، ويتحقق من البصمات ويمنع مسارات ZIP غير الآمنة. تنزيل أدوات المتصفح يستخدم npm مع ignore-scripts، ولا يعيد تنزيل Chromium. يمكن تمرير source-cache خاص يحوي الأرشيفات نفسها لتجنب إعادة التنزيل؛ لا يقبل أرشيفًا مخالفًا للبصمة.

بعد موافقة المراجع على ملفات الحزمة شغّل باستخدام المسار المطبوع، مثل المسار التوضيحي التالي:

```bash
python3 scripts/run_compatibility_lab.py run --state /home/chatbot/.local/state/menyona-compatibility/run-EXAMPLE
```

يبني صورة محلية دون شبكة أثناء البناء، وينشئ بيانات وهمية، ويجرب الطلب عبر صفحة الدفع الكلاسيكية ووسيلة الدفع عند الاستلام المحلية. يجرب CLI منفصل إجمالي الطلب والمخزون وتكرار انتقال الدفع المحاكى، وHPOS والصلاحيات. تفحص الاختبارات عدم عبور شبكة مطعم إلى الآخر، والمنافذ والموارد والملفات، وحفظ الطلب بعد إعادة التشغيل. إذا منع المضيف sandbox تحفظ بقية أدلة CLI والعزل مع browser=BLOCKED، ويظل الخروج غير صفري؛ أي خطأ آخر لا يعاد تصنيفه كمانع بيئي. توقف الحاويات في النهاية وتحتفظ بالوحدات الوهمية للمراجعة؛ لا تستخدم prune أو حذفًا عامًا.

للإيقاف في حالة المقاطعة استخدم الحالة نفسها؛ يتحقق الإيقاف من هوية المشروع وعلامة الحالة فقط، فيعمل أيضًا بعد تعديل مصادر المختبر دون تنفيذ ملف Compose المعدل:

```bash
python3 scripts/run_compatibility_lab.py stop --state /home/chatbot/.local/state/menyona-compatibility/run-EXAMPLE
```

يحفظ evidence.json الخاص النتائج المنقحة. قد يحوي command-failure.txt الخاص تشخيصًا خامًا عند فشل أمر؛ لا ينشر هذا الملف أو credentials.json أو ملفات cookies أو package cache. تتحقق بصمات Compose وسياق البناء وأدوات JavaScript وChromium قبل التشغيل. تغيير مصادر المختبر يبطل تشغيل الحالة السابقة ويستلزم تحضيرًا ومراجعة جديدين. run معد لتثبيت جديد واحد؛ لا يعيد تهيئة قاعدة قائمة أو يحذفها ليكرر الاختبار.

## حدود الإتاحة والقبول

فحص المتصفح يجرب التنقل بلوحة المفاتيح، وحقولًا ذات تسميات، وشجرة Accessibility، وaxe-core. يعمل Chromium مع sandbox فعلي وحظر Service Workers وطلبات الصفحات الخارجية؛ تعذر sandbox مانع مسجل ولا يعالج بتعطيله صامتًا. يسجل axe حالة PASS أو FAIL ومخالفاته بدل إخفائها. هذا فحص آلي وجزئي؛ استخدام قارئ شاشة فعلي ما زال NOT_RUN حتى ينفذه مستخدم به. نجاح المحاكاة لا يغير حالة بوابة الدفع إلى PASS، كما تبقى HTTPS وCaddy والاستعادة من نسخة احتياطية والعنوان والتوصيل وبقية وظائف المنتج خارج قبول هذه التجربة.

المصادر: [متطلبات WooCommerce](https://woocommerce.com/document/server-requirements/)، و[صورة WordPress الرسمية](https://hub.docker.com/_/wordpress)، و[واجهات HPOS](https://developer.woocommerce.com/docs/features/orders/high-performance-order-storage/recipe-book/)، و[Storefront](https://woocommerce.com/products/storefront/).
